# Getting Started with Krewire Community Portal

This guide explains how to develop, preview, and build the **`krewire.github.io`** community portal locally.

---

## Prerequisites

1. **`kiw` CLI**: Built from the `krewire` repository:
   ```bash
   cd /home/reasvyn/workspace/krewire/krewire
   go build -o ../bin/krew ./cmd/krew
   ```
2. **Git**: Configured for interacting with the repository.
3. **No Local Go Dependencies**: As a static site project, `krewire.github.io` runs directly via the `kiw` devtool without needing a `go.mod` file.

---

## Local Development Workflow

### 1. Build Static Artifacts

Compile the portal into `.krewire/build/`:

```bash
cd /home/reasvyn/workspace/krewire/krewire.github.io
kiw build
```

This command parses the `.kiw` files in `pages/`, applies the layouts in `layouts/`, bundles static assets from `public/`, and produces ready-to-deploy static files.

### 2. Live Preview

Run the development server to test changes with live reload:

```bash
kiw serve
```

Open `http://localhost:8080` in your web browser.

## Working with Portal Content

### Page Structure & Routing

- `pages/index.kiw`: The main single-page community portal containing sections for:
  - Hero.
  - Start Here: canonical path to a first project (links to krewire.com) and a "where things live" map.
  - Why Contribute (no unapproved perk or license programs).
  - Public repository matrix.
  - Contributor guide and quality gates (mirroring core `CONTRIBUTING.md`).
  - Governance.
  - Support information (verified channels only).
  - Community & support channels.
  - AI Boost workflow intro.

### Localization & Bilingual Parity (Single Source of Truth)

- Content is localized across English (`en`) and Indonesian (`id`) with full 100% key parity.
- Canonical localization dictionaries are stored strictly under `lang/en/portal.json` and `lang/id/portal.json`.
- Root-level redundant files (`lang/en.json`, `lang/id.json`) are deprecated and removed to prevent overlapping sources of truth.
- Fallback locale is configured as `en` in `krewire.yaml`.
- The runtime client-side language switcher reads the synchronized dictionaries embedded in `public/assets/krewire.js` (`var translations = {...}`).
- When adding or updating portal copy, update `lang/en/portal.json` and `lang/id/portal.json` first, then sync the embedded JSON in `public/assets/krewire.js`.

### Directory & Asset Ownership

- `pages/`: Page entrypoints (`index.kiw` for single-page portal, 404 handler).
- `layouts/`: Master shell (`Landing.kiw` and `Base.kiw`).
- `lang/`: Canonical i18n dictionaries (`lang/{locale}/portal.json`).
- `public/`: Authored static assets (favicons, images, brand logos, CSS/JS).
- `.krewire/build/`: Ephemeral generated output from `krew build` (excluded via `.gitignore`). Never commit generated build artifacts to source tree.

### Theme & Design Tokens

Theme colors are defined in `krewire.yaml` under `theme:`:
- Light theme: Crisp paper base (`#FAF8F4`) with primary emerald (`#39D353`) and brand navy (`#0B1F3B`).
- Dark theme: Dark navy base (`#0B1F3B`) with emerald accents.
- Scoped component styles use `data-kiw-*` attributes automatically generated by `kiw build`.
