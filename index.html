Ecosystem Release

Krewire Ecosystem v0.1.0 Launch

The foundational milestone release delivering single monorepo architecture, the kiw devtool, strictly typed manifests, and 8 unified workload shapes.

📦

Single Monorepo Architecture

Consolidated under github.com/krewire/krewire. Eliminates cross-module dependency fragmentation, guarantees atomic Git commits, and powers seamless Go workspaces (go.work).

⚡

Unified 'kiw' Devtool CLI

A single binary driving the software lifecycle: kiw new, kiw dev, kiw build, kiw serve, kiw worker, kiw deploy, and kiw boost.

⚙️

One Config: krewire.yaml

Strictly typed, declarative project manifests eliminating arbitrary configuration drift across all 8 supported workloads.

🧩

Modular Domain Libraries

Single-purpose packages under packages/* (kern, web, ui, cli, db, config, validation, fs, worker). Compose only what you need without inheriting a monolithic framework.

🤖

AI Boost & Agent Triad Native

First-class integration for autonomous AI developer agents (templates/boost) with formal KWF-* specifications, automated audits, and regression tests.

📖

Independent Docs Engine (mdbind)

Standalone Markdown book & docs compiler powering the book kind with AST transformations, live reloads, and offline assets embedding.

Quick Installation

Get Started in Seconds

Install the kiw developer tool, scaffold an application, or bootstrap the entire 5-repository workspace.

1

1. Install kiw CLI

Install the unified developer toolchain globally via Go:

go install github.com/krewire/krewire/tools/kiw/cmd/kiw@latest
2

2. Scaffold a Project

Generate a fullstack application or any of the 8 workloads:

kiw new my-app --kind=app
cd my-app
3

3. Run Locally

Start hot-reloading dev server with instant feedback:

kiw dev

Quality Assurance

The Krewire Way: 3 Quality Gates

To keep the codebase reliable, predictable, and production-ready, every pull request passes through three automated gates.

1

Gate 1: Format & Lint

Zero lint errors and idiomatic Go formatting. Code must adhere strictly to Go standard conventions.

gofmt -s -l .
go vet ./...
Required: Clean exit, 0 warnings
2

Gate 2: Race & Tests

Every commit is verified with race condition detection and comprehensive unit & integration tests.

go test -race ./...
go build ./...
Required: 100% test pass, 0 data races
3

Gate 3: Spec & Commits

Changes must link to a valid Spec or Issue, following Conventional Commits format.

feat(scope): implement workload runner
fix(web): recover panic in http handler
Required: Semantic versioning compliance
