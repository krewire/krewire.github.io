Quality Assurance

The Krewire Way: 3 Quality Gates

To keep the codebase reliable, predictable, and production-ready, every pull request passes through three automated gates.

1

Gate 1: Format & Lint

Zero lint errors and idiomatic Go formatting. Code must adhere strictly to Go standard conventions.

go fmt -s ./...
go vet ./...
Required: Clean exit, 0 warnings
2

Gate 2: Race & Tests

Every commit is verified with race condition detection and comprehensive unit & integration tests.

go test -race -cover ./...
kiw build
Required: 100% test pass, 0 data races
3

Gate 3: Spec & Commits

Changes must link to a valid Spec or Issue, following Conventional Commits format.

feat(runner): implement parallel workloads
fix(web): recover panic in http handler
Required: Semantic versioning compliance
Getting Started

Start Contributing in 5 Steps

From zero to your first merged pull request. Here is how to get your development environment running in minutes.

1

Fork & Clone the Repositories

Fork any Krewire repository to your personal GitHub account, then clone it locally:

git clone https://github.com/<your-username>/framework.git
cd framework
2

Initialize Multi-Module Workspace

If you're working across multiple Krewire repos, sync your local Go workspace seamlessly:

go work init ./
go work use ./
go work sync
3

Pick an Open Issue

Browse our curated issues list tagged with good-first-issue or help-wanted. Comment on the issue to let the community know you're working on it.

View Good First Issues →
4

Implement & Verify Locally

Write clean code and corresponding tests. Verify that all 3 Quality Gates pass with zero failures:

go test -race ./...
# For website changes:
kiw build
5

Submit Pull Request & Collaborate

Open a Pull Request with Conventional Commits. The maintainers and the AI Guild will review, provide fast feedback, and guide you to merge.
